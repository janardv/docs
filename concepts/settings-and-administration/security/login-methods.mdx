Login methods determine how users authenticate into Oculon. Current Settings expose personal sign-in options and workspace-level two-factor expectations.

## Personal sign-in options

Under **My Account → Security**, people can manage:

- Email password set or reset
- Google connect
- Two-factor authentication
- Session logout

Exact options depend on how the account was created and what the workspace requires.

## Workspace two-factor requirement

Workspace Owners can require two-factor authentication under **Admin → Security and Access**. When enabled, members should expect stronger authentication before they continue working in the workspace.

## Central identity and SSO

A dedicated SSO / SAML / SCIM configuration UI is **not** confirmed in the current Settings overlay. Do not treat SSO setup as a generally available self-serve Settings workflow from Concepts.

If your organization requires centrally managed identity, confirm plan support and onboarding with Oculon rather than following older SSO-only documentation as current UI instructions.

## Communicate changes clearly

Any change to sign-in or 2FA requirements affects every user. Announce the change, explain the cutover path, and provide a support route.
