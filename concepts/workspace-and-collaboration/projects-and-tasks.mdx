**Projects** is a work surface for coordinating people, tasks, AI context, and project activity. It is separate from [Spaces](/concepts/workspace-and-collaboration/teamspaces-and-private-space), which organize planning assets in the content tree.

## Availability

Projects is feature-flagged.

- On by default in local and sandbox environments
- Off by default in development, staging, and production

If you do not see **Projects** in the sidebar, the feature is not available in your workspace. Do not treat Projects as generally available across all workspaces.

## What Projects is for

Use Projects when you need a place to:

- Track work with tasks, owners, due dates, and status
- Keep project-scoped chats, instructions, and files together
- Review project activity without mixing it into model version history

Open **Projects** from the sidebar (`/projects`) when the feature is enabled.

## Projects vs Spaces

| Concept | Role |
| :--- | :--- |
| **Projects** | Work management: tasks, activity, project AI context, optional sprints |
| **Spaces / Teamspaces** | Content placement for models, Transactions, boards, and related assets |

You can place a project in a Space for navigation. Access to the project still comes from project and workspace sharing, not from Space membership alone. See [Project settings and access](/concepts/workspace-and-collaboration/projects-and-tasks/project-settings-and-access).
