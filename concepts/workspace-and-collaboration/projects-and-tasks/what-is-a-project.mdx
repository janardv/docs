A **project** is a container for coordinated work in Oculon. It groups tasks, project-scoped chats, instructions, files, and activity so a team can track progress in one place.

Projects are available only when [Projects and tasks](/concepts/workspace-and-collaboration/projects-and-tasks) is enabled for your workspace.

## What a project owns

A typical project includes:

- A name, summary, status, lead, dates, and priority
- Tasks with assignees, status, and due dates
- Overview notes and linked files
- Project instructions and shared project memory for AI
- An [Activity](/concepts/workspace-and-collaboration/projects-and-tasks/project-activity) feed for project and task events

## When to use a project

Create a project when work needs owners, status, and follow-through—for example a close process, a forecast refresh, or a reporting package with multiple contributors.

Prefer Spaces and Library assets when you are organizing models, Transactions, or boards without a task workflow.

## Projects are not Spaces

Spaces organize where planning assets live. Projects organize how work gets done. Placing a project under a Space helps navigation. It does not replace project sharing and access controls.
