Projects has two main layers: the portfolio at `/projects`, and the detail page for a single project.

Availability follows [Projects and tasks](/concepts/workspace-and-collaboration/projects-and-tasks).

## Portfolio

The Projects index uses tabs:

| Tab | What you see |
| :--- | :--- |
| **Projects** | Project catalog (name, status, tasks, lead, target, chats, last activity) |
| **All tasks** | Tasks across projects you can open |
| **My tasks** | Tasks assigned to you or waiting on your review |

From the portfolio you can create a **New project** or **New task**, search, and filter (including shared and archived projects).

## Project detail

Open a project to work inside it. Built-in areas include:

| Area | Purpose |
| :--- | :--- |
| **Overview** | Summary, notes, files, agent tasks, and project context |
| **Tasks** | Project task list and views |
| **Activity** | Project-scoped event history |
| **Chats** | Chats scoped to the project |

Optional **Sprints** features can add sprint tabs when enabled for that project. Sprints are opt-in. Treat them as an optional project feature, not a separate product area.

## Custom views

Projects can include additional view tabs you configure. A board tab named something like “Plan” is a custom view name, not a separate Plans product object.
