**Tasks** are the units of work inside Projects. Use them to assign ownership, track status, and move work to completion.

Tasks are available only when [Projects and tasks](/concepts/workspace-and-collaboration/projects-and-tasks) is enabled.

## Where tasks appear

| Surface | Scope |
| :--- | :--- |
| Project **Tasks** | Tasks in one project |
| Portfolio **All tasks** | Every task in every project you can open |
| Portfolio **My tasks** | Tasks assigned to you or waiting on your review |

You can also open a task on its own route when linked (`/tasks/...`).

## Core task fields

Confirmed core fields include:

| Field | Use |
| :--- | :--- |
| **Title** | What the work is |
| **Status** | Progress state for the task type |
| **Assignee** | Person or agent responsible |
| **Reviewer** | Optional reviewer |
| **Due date** | When the work is due |
| **Priority** | None, Low, Medium, High, or Urgent |
| **Project** | Which project the task belongs to |
| **Linked file** | Optional linked planning asset |

Task types can add custom fields. Status rules may lock some custom fields until status changes. Treat advanced custom-field behavior as configurable, not identical in every workspace.

## Create and update tasks

- Create from **New task** on the portfolio or inside a project.
- Edit fields inline in lists or from the task detail panel.
- Move tasks between projects when the product allows a move preview and confirm.
- Use list or board views where available (including status columns on boards).

## Assign people and agents

Assignees can be people or agents. When an agent is assigned, the project can show **Agent tasks** run controls (including stop or steer) while a run is active.

Agent assignment depends on agents being available in your workspace. Keep expectations aligned with [Custom agents](/concepts/ai-and-agents/custom-agents) and [AI in projects](/concepts/workspace-and-collaboration/projects-and-tasks/ai-in-projects).
