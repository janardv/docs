Project settings control how a project behaves and who can change it. Availability follows [Projects and tasks](/concepts/workspace-and-collaboration/projects-and-tasks).

## Project settings menu

From a project, open the project settings menu for actions such as:

- **Project properties**
- **Change task type**
- **Repeat** (recurring project settings when used)
- **Features** (for example turn **Sprints** on or off)
- Lifecycle actions: complete, duplicate, save as template, archive, restore, delete

Exact menu items depend on your access level.

## Workspace project settings

`/projects/settings` manages shared configuration such as:

- **Task types**
- **Project properties**
- **Core task fields**

Core fields stay consistent so **My tasks**, progress, and agents can work across types.

## Access and sharing

Project access uses the same permission vocabulary as other shared resources (**View**, **Edit**, **Full access**). See [Sharing and permissions](/concepts/workspace-and-collaboration/sharing-and-permissions) for the shared model.

In Projects UI:

- **Workspace access** / **Access** opens sharing for the project
- Catalog menus include **Share projects** and **Copy link**
- Editing typically requires edit access
- Archive, delete, and restore typically require **Full access**

Space placement does not replace these controls. A project listed under a Space can still require separate project access.

## Permissions boundary

This page covers project-specific settings and access entry points only. Workspace roles, invitations, and generic sharing concepts stay in Settings and Sharing docs.
