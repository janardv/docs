Time settings affect every formula and report in a model. A few habits keep them predictable as the model grows and changes hands.

## Set time before you build

Confirm the granularity, date range, Last actual date, and fiscal year setting before you write complex formulas. Changing these later affects formulas, views, and boards at once.

## Make close a routine

Move the Last actual date as a fixed step in each close:

1. Refresh the Transactions the model reads from.
2. Move the Last actual date to the newly closed period.
3. Review the last actual period and the first planned period.
4. Check the quarter and year totals your reports use.

Give one person ownership of this step so the whole team works from the same cutoff.

## Use relative time instead of fixed dates

Use [relative time](/concepts/data-and-structure/time/relative-time) references such as `Previous month` when a rule should hold in every period. A formula that points at a fixed month needs editing each time the model moves forward.

## Set aggregation for every non-additive metric

Time aggregation defaults to **Sum**. Before you share a model, check each balance and rate variable:

- Set balances such as headcount or cash to **Final**.
- Set opening balances to **Initial**.
- Review rates and percentages so the quarter value isn't a sum.

See [Time rollups and aggregation](/concepts/data-and-structure/time/time-aggregation).

## Review summaries, not only months

Monthly values can be correct while quarter or year values are wrong. Add a **Month → Quarter → Year** rollup to a view and check the totals before you share the model.

## Common mistakes

- Changing granularity after formulas and boards are in use
- Leaving fixed-date references in formulas that should roll forward
- Summing a balance metric, such as headcount, across a quarter
- Moving the Last actual date without checking the first planned period
- Turning the fiscal year setting on or off after reports depend on quarter and year columns

## Checklist before you share a model

- The date range covers the planning horizon.
- The granularity matches how often the team reviews and updates.
- The Last actual date matches the last closed period.
- Balance and rate variables use the right time aggregation.
- Quarter and year rollups show the values you expect.
