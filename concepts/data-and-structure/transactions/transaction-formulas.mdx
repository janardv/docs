You can enter a formula in a Transactions cell instead of a fixed value. Type a value that starts with `=`, such as `=1200 * 12`, in a variable cell. Oculon saves it as a formula override on that cell.

## How cell formulas work

- A formula applies to one cell in a variable column, such as `Amount` or `MRR`.
- Oculon saves the formula as an override. The source value for that cell stays unchanged underneath.
- To remove the formula, clear the cell.
- Formulas use the same syntax as model formulas. See [Formula basics](/concepts/modeling/formulas/formula-basics).

Dimension columns and date columns don't take formulas. In a dimension cell, you pick a dimension value instead.

## When to use a cell formula

Use a cell formula for a small, record-level correction. For example, you can annualize one monthly amount, or split a value that a source system recorded as one total.

If many rows need the same correction, fix it at the source or in the query instead. One-off formulas are hard to review when they spread across a table.

## Transaction formula versus model formula

| Use a Transactions cell formula when | Use a model formula when |
| :--- | :--- |
| The fix belongs to one record | The rule applies to a whole variable |
| Reviewers need to see the correction next to the source row | The logic depends on drivers, scenarios, or other models |
| The value is an actual that the source got wrong | The value is a plan for periods after the Last actual date |

Models decide how values behave across the [Last actual date](/concepts/data-and-structure/time/last-actual-date). A variable's **actual formula** reads Transactions values up to that date. Its **planned formula** calculates the periods after it. Keep that logic in the model, not in Transactions cells.
