Well-organized variables make a model easier to build, review, and trust. Use these habits from the first draft.

## Name and type

- Use business names your team already uses, such as `Gross Profit` rather than `GP calc 2`.
- Choose the [type](/concepts/data-and-structure/variables/variable-types) that matches the meaning. Use **Currency** for money and **Percentage** for rates.
- Use the same formatting for similar variables in a model.

## Structure

- Separate inputs, calculations, and outputs into different sections.
- Add a breakdown only when you need to analyze by that dimension. See [Using dimensions with variables](/concepts/data-and-structure/dimensions/using-dimensions-with-variables).
- Split long formulas into short helper variables. See [Formula best practices](/concepts/modeling/formulas/formula-best-practices).

## Actual and planned logic

- Keep the actual formula tied to source data, such as Transactions.
- Keep the planned formula tied to drivers and assumptions.
- Use period overrides for true one-off exceptions, not as a substitute for a formula.

## Review before you scale

Before a model grows, check that names, sections, and references still make sense. A small cleanup early is easier than a large restructure later.

## Protect shared logic

If a variable feeds many boards or other models, treat it as shared. Review changes with the people who depend on it.
