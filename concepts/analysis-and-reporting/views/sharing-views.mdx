Views help people work from a focused slice of a model or Transactions dataset. How you share that slice depends on what the product currently supports.

## Current sharing support

Dedicated **Share View** controls are not generally available yet.

- On models, **Share View** is shown as coming soon
- On Transactions, view-level Share is hidden until it ships

Do not treat a dedicated view-share dialog as a generally available workflow.

## What you can do today

Use these supported patterns instead:

- **Copy link** to a saved view when the views menu offers it, so someone opens the intended slice (permissions still apply)
- Share the underlying **model** or **Transactions** resource at the right access level
- Put the view on a **board** when people need a curated presentation rather than the full source

For item access levels, see [Sharing and permissions](/concepts/workspace-and-collaboration/sharing-and-permissions) and [Roles and permissions](/concepts/workspace-and-collaboration/sharing-and-permissions/roles-and-permissions).

## Private views are not supported

Oculon does not support private views. Treat saved views as team-facing configurations. Create them when the definition is ready to be reused or reviewed by others.

## Review before you hand off a view

Before you send a view link or rely on a board that uses the view:

1. Confirm the filters show only the intended content
2. Confirm the source model or Transactions dataset is current
3. Confirm the audience can access the source and any board context they need
4. Preview the view the way the audience will use it

## Choose the right surface

Use a view when people need filtered detail. Use a board when they mainly need a curated presentation of the result. Share the full model only when they also need the underlying planning surface.
