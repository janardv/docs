A small set of concepts explains most of how Oculon behaves. This page defines each one and says why it matters. To learn where these concepts live in the product, see [How Oculon is organized](/concepts/core-concepts/how-oculon-is-organized).

## Model

A model is where your planning logic lives. It contains variables laid out across time, plus the settings that control how they calculate.

**Why it matters:** the model is the single source for a number. Views, comparisons, and boards all read from it, so a change made once flows through to every report.

[Models →](/concepts/modeling/models)

## Variable

A variable is one line in a model, such as `Revenue`, `Units Sold`, or `Headcount`. It can hold input values, a formula, or both.

**Why it matters:** you define a metric once and reuse it everywhere. You don't rebuild the same calculation in each report.

[Variables →](/concepts/data-and-structure/variables)

## Formula

A formula tells a variable how to calculate. It can reference other variables, Transactions, dimensions, and relative time such as `This month` or `Previous month`. Each variable can have an **actual formula** and a **planned formula**.

**Why it matters:** formulas turn assumptions and source data into results. Splitting actual and planned logic lets one variable show real history and a forecast without manual switching.

[Formulas →](/concepts/modeling/formulas)

## Time

Every model has a time setup. The setup has a granularity (`monthly`, `quarterly`, or `yearly`), a date range, and a [Last actual date](/concepts/data-and-structure/time/last-actual-date). Periods up to the Last actual date use the actual formula. Later periods use the planned formula.

**Why it matters:** time settings decide which logic applies in each period. They also decide how monthly values roll up into quarters and years.

[Time →](/concepts/data-and-structure/time)

## Dimension

A dimension is a shared category, such as `Region`, `Product`, or `Department`, with values such as `EMEA` and `APAC`. Dimensions belong to the whole workspace, so many models can use the same one.

**Why it matters:** one variable can be broken down by category, so you don't need a separate variable for each region or product.

[Dimensions →](/concepts/data-and-structure/dimensions)

## Transactions

Transactions hold your source records, such as ledger entries, invoices, or CRM deals. The records come from an integration, an uploaded file, or manual entry.

**Why it matters:** Transactions give models a reliable source for actuals. When the source data refreshes, linked models pick up the new values.

[Transactions →](/concepts/data-and-structure/transactions)

## Scenario

A scenario is a branch of your planning data. Every workspace starts with **Default Scenario**. Other scenarios inherit its values until you override them.

**Why it matters:** you can test a hiring plan or a pricing change without touching the baseline. You can then compare the results before you merge anything.

[Scenarios →](/concepts/modeling/scenarios)

## View and Compare

A view is a saved way of looking at a model or Transactions. A model view stores the date range, filters, sorting, and rollups. A Transactions view stores filters, sorting, and grouping. Compare is a view setting that shows scenarios or time periods side by side, with the variance between them.

**Why it matters:** different people need different slices of the same model. Views give each of them a focused, repeatable lens, and nobody has to copy data.

[Views →](/concepts/analysis-and-reporting/views) · [Compare →](/concepts/analysis-and-reporting/compare)

## Board

A board is a reporting page. You combine charts, tables, and KPI blocks built from your models and data on one board.

**Why it matters:** boards are how results reach stakeholders. Because boards read live from models, they stay current as the plan changes.

[Boards →](/concepts/analysis-and-reporting/boards)

## AI assistant

The AI assistant is a chat you can open from any page. It can explain, build, and change models and reports. You choose whether it asks before it makes changes.

**Why it matters:** routine modeling and reporting tasks go faster. The assistant works within your permissions and acts on the same objects you do.

[AI overview →](/concepts/ai-and-agents/ai-overview)
