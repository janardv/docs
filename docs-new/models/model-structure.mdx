A clear model structure makes a model easier to build, review, and maintain.

![Model breakdown view in Oculon](/images/getting-started/fr-model-breakdown.png)

## Common structural layers

- sections for major business areas
- variables inside each section
- helper logic that supports larger calculations
- dimensions applied where extra detail is needed
- outputs that feed views, boards, and scenario review

## A practical structure pattern

Many teams structure a model in this order: assumptions, drivers, calculations, outputs. This keeps the logic readable and makes it easier to trace how an output is built.

## What good structure helps you do

Good structure helps you:

- review formulas without scanning unrelated lines
- separate inputs from calculated logic
- keep helper variables close to the outputs they support
- make scenario changes easier to test

## Keep the model readable as it grows

A small model can tolerate loose structure. A shared model cannot. Once scenarios, linked models, and board reporting rely on the same logic, structure becomes a maintenance issue, not just a style preference.
