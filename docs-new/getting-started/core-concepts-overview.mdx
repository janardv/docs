Most work in Oculon comes down to a small set of concepts that build on each other. Once you understand how they connect, the rest of the product is much easier to navigate.

## Variables

Variables are the core lines in a model. They hold values, formulas, or both. A variable can represent a metric, a driver, an assumption, or a calculated result.

## Dimensi'ons.

Dimensions add structure to a variable. You use them to break the same metric into categories such as region, department, product, or customer segment.

## Time

Time gives the model a planning horizon. It defines the date range, granularity, and the point where actuals end and forecast values begin.

## Formulas

Formulas tell variables how to calculate. They can reference other variables, use helper logic, and respond to time and dimension context.

## Models, databases, scenarios, views, and boards

- `Models` hold the planning logic.
- `Databases` hold source records and imported data.
- `Scenarios` let you test changes safely.
- `Views` save filtered slices of model or database content.
- `Boards` present metrics visually and can embed saved views.

## A good mental model

Think of Oculon as one connected system: 
- `Databases` provide data
- `Models` create logic
- `Scenarios` test change
- `Views` narrow the right model or database slice
- `Boards` communicate the result
