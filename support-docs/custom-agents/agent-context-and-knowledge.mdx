An agent is only as useful as the context you give it.

## Good context sources

Useful context can include model structure, approved terminology, workspace rules, selected boards, operating definitions, and scoped internal guidance.

## Avoid overloading the agent

More context is not always better. Too much mixed information makes answers less consistent and harder to review.

## Keep knowledge current

If the underlying model, policy, or workflow changes, update the agent context as part of the same release. Stale instructions are one of the fastest ways to reduce trust.
